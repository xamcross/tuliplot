# SEO Wave 2 (Real 404s + Head Resets) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unknown URLs return real HTTP 404s with a branded page (today they soft-404 as the homepage), and stale head state is reset on `/login`, `/register`, and guide/blog not-found views — Wave 2 of `docs/seo/2026-08-01-seo-audit-remediation.md` plus its recorded follow-ups.

**Architecture:** A `NotFoundComponent` backs both a client-side `**` route and a prerendered `/404` server route; a postbuild script copies the prerendered page to `dist/…/404.html`, which Cloudflare Pages serves with status 404 for unmatched paths once the `_redirects` catch-all (`/* /index.html 200` — the soft-404 mechanism) is narrowed to exactly the client-rendered routes: `/login`, `/register`, `/app`, `/app/*`. **Correction to the roadmap's wording:** it says narrow to `/app*` only, but `/login`/`/register` are `RenderMode.Client` (no prerendered HTML exists for them) — without their rewrite lines, login breaks. Head resets ride on the existing `SeoService` (calling `set()` without `jsonLd` also purges stale structured data).

**Tech Stack:** Angular 20 standalone (prerender via `@angular/ssr` server routes), Cloudflare Pages `_redirects`/`404.html` semantics, `wrangler pages dev` for local edge-behavior smoke tests, Vitest + TestBed (zoneless).

**Roadmap:** item 2.1 + the "Wave 2" follow-up line in `docs/seo/2026-08-01-seo-audit-remediation.md`. Wave-3 pre-reqs listed there are OUT of scope.

### Task 2: postbuild copy of the prerendered 404

**Files:**
- Create: `frontend/scripts/copy-404.mjs`
- Modify: `frontend/package.json` (add `postbuild` script)

**Interfaces:**
- Consumes: `dist/frontend/browser/404/index.html` produced by Task 1's prerender.
- Produces: `dist/frontend/browser/404.html` — the file Cloudflare Pages automatically serves with **status 404** for any unmatched path (once Task 3 removes the catch-all rewrite). Runs automatically via `npm run build` (which CI's deploy pipeline uses).

- [ ] **Step 1: Write the script**

Create `frontend/scripts/copy-404.mjs`:

```js
// Cloudflare Pages serves a root-level 404.html with status 404 for unmatched
// paths. Angular prerenders the /404 route to 404/index.html; copy it up.
// Runs as npm postbuild. Fails loudly if the prerender is missing.
import { copyFileSync, existsSync } from 'node:fs';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

const browserDir = resolve(dirname(fileURLToPath(import.meta.url)), '../dist/frontend/browser');
const src = resolve(browserDir, '404/index.html');
const dest = resolve(browserDir, '404.html');

if (!existsSync(src)) {
  throw new Error(`copy-404: prerendered ${src} not found — is the /404 route in app.routes.server.ts?`);
}
copyFileSync(src, dest);
console.log(`copy-404: ${src} -> ${dest}`);
```

- [ ] **Step 2: Add the npm hook**

In `frontend/package.json` scripts, next to the existing `"prebuild"` line, add:

```json
    "postbuild": "node scripts/copy-404.mjs",
```
